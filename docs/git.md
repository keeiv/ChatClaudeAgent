# 版本控制與額度自動接續（1.0.1-luna，登入頁 1.0.1-terra）

## 版本控制面板

頻道標題列的分支圖示，或群組側欄「工作區 → 版本控制」，開啟目前對話專案資料夾的 Git 面板（CLI：`/git`）。面板與審查窗格共用聊天區，開一個會關掉另一個；開啟期間成員欄讓出空間。

**先登入。** 每次開啟面板，CCA 先對第一個遠端執行 `git ls-remote`（不跳出任何視窗，最多 20 秒），畫面顯示「確認登入狀態」。遠端回報需要登入，或 Git 還沒有提交身分（`user.name`、`user.email`）時，面板先顯示登入頁，不列出檔案：

- HTTPS 遠端：按「使用瀏覽器登入 主機」，CCA 讓 Git 認證管理員（Git Credential Manager）開自己的登入視窗或瀏覽器，最多等 5 分鐘。帳號密碼只在那個視窗或瀏覽器輸入，CCA 沒有密碼欄位，也看不到、不保存；登入結果由 Git 認證管理員存進 Windows 認證管理員。這台電腦沒有設定 `credential.helper` 但有 Git 認證管理員時，按下登入會一併設定 `credential.helper=manager`（全域）；兩者都沒有時請先安裝 Git for Windows。
- SSH 遠端：CCA 不建立或讀取金鑰，登入頁列出 `ssh-keygen` 與加入公鑰的步驟，完成後按「重新檢查」。
- 提交身分：填名稱與 e-mail，預設套用到這台電腦所有倉庫（`git config --global`），取消勾選只寫進目前倉庫（CLI：`/git identity 名稱 e-mail`，加 `--repo` 只寫目前倉庫）。

「先略過，只用本機提交」可以直接進入檔案選擇；標題列會留下「需要登入」或「未設定提交身分」標記，點一下回到登入頁。之後的擷取、拉取、推送或自動擷取若因登入失敗，CCA 會重新檢查並回到登入頁，自動擷取暫停到登入完成為止。連不上遠端（離線、DNS 失敗、逾時）不算未登入，只在標題列顯示「無法連線遠端」。

**選檔提交。** 每個變更檔案是一張圖示卡，先看顏色就知道狀態：

| 顏色 | 意思 | 預設 |
| --- | --- | --- |
| 黃色 | 修改、刪除或改名 | 已選取 |
| 綠色 | 新增（未追蹤或已暫存的新檔） | 已選取 |
| 紅色 | 不建議提交：疑似金鑰或憑證（`.env`、`*.pem`、`id_rsa*`…）、建置產物與相依套件（`build/`、`node_modules/`…）、二進位檔、暫存或記錄檔、大於 5 MB、未解決的衝突 | 不選；點選時再確認一次 |
| 紅色虛線加盾牌 | 符合「永遠不提交」規則 | 鎖定，無法選取 |

點卡片切換選取；滑過卡片可「查看差異」或「加入永遠不提交規則」。提交訊息可按「依任務紀錄草擬」，從目前任務的需求與選取檔案產生，不呼叫模型。勾選「附上任務編號」時，訊息加上 `CCA-Task: <任務編號>`，提交紀錄圖會把這些提交標成 CCA。

主機在提交前重新讀取 Git 狀態再檢查一次：鎖定的檔案、未經確認的紅色檔案、不在目前變更裡的路徑都會被拒絕，不只靠畫面。提交只包含選取的路徑（`git commit -- 路徑`），其他已暫存的內容不會被帶進去。

**提交前金鑰掃描。** 選取的檔案暫存後，CCA 掃描新增的行：私鑰、AWS 存取金鑰、`sk-` 開頭的 API 金鑰、GitHub 與 Slack 權杖、Google API 金鑰，以及寫死的密碼或權杖。發現時取消暫存、不提交，列出檔案、行號與類型（不顯示金鑰本身）；確認不是金鑰後可「仍要提交」（CLI：`/git commit! 訊息`）。

**推送與同步。** 「提交並推送」在提交後推送；沒有追蹤分支時推送到第一個遠端並設定追蹤。「擷取」「拉取」「推送」按鈕顯示領先／落後數量。拉取只做快轉（`--ff-only`），有分歧時 Git 會拒絕並顯示原因。勾選「自動擷取」後每 1～60 分鐘擷取一次；再勾「自動拉取」時，只在這個對話的 AI 都沒有工作、本地沒有領先時快轉拉取，完成後跳出提示。

**提交紀錄圖。** 右側列出最近 150 筆提交（所有分支），以泳道圖畫出分支與合併，顯示分支、標籤、遠端參照、作者與時間；來自 CCA 任務的提交是空心節點加 CCA 標記。

**限制。** 除了登入頁的登入動作，所有 Git 指令都在背景執行，帶 `GIT_TERMINAL_PROMPT=0`、`GCM_INTERACTIVE=never`，需要帳密的遠端會直接失敗而不是卡住。AI 工作中不能提交、拉取或推送。遠端網址與錯誤訊息裡的帳密不會顯示。

## 永遠不提交規則

設定 → 版本控制（CLI：`/git never 規則`、`/git allow 規則`）。規則寫法同 `.gitignore`：只寫名稱比對任何位置，結尾 `/` 代表資料夾，含 `/` 從專案根目錄比對，`**` 可跨資料夾，不分大小寫。規則存在本機 `settings.json`，不寫進專案，適用所有專案。新安裝預設 `.env`、`.env.local`、`*.pem`、`*.key`、`*.pfx`、`id_rsa*`、`.cca-artifacts/`；設定頁另列常用規則可一鍵加入。

## 額度與自動接續

群組或多代理流程的所有 AI 額度用完時，CCA 強制停止並記錄下一步（見 [Gemini 文件](gemini.md)）。設定 → 額度與自動接續（CLI：`/resume-auto on|off`）可開啟自動接續：

- 接續時間 = 各成員最早的額度重置時間 + 延後分鐘數。重置時間來自 Claude 的額度事件與 GPT 回報的用量視窗；沒有回報時用各 AI 的預設等待（預設 Claude 300、GPT 300、Gemini 60 分鐘，可自行調整）。帳號已停用的 Gemini 不列入。
- 可限定只在某時段接續（例如 23:00～07:00，可跨午夜）；排程落在時段外會延到下一個時段開始。
- 到時間且 CCA 開著、任務沒有被手動接續時自動接續，聊天顯示「額度預計已恢復，自動接續任務（第 N 次）」。接續後仍沒有額度會再排下一次，超過最多次數（預設 3）就停止自動接續；任務完成後次數歸零。
- 任務紀錄卡顯示排定時間，可「取消自動接續」或「排定額度恢復後自動接續」。
- 預設等待也決定被「跳過」的成員多久後再試。

## 驗證

```powershell
.\build.bat test        # 規則比對、狀態解析、顏色分類、金鑰掃描、提交紀錄解析、登入錯誤分類、遠端主機解析
.\build.bat git-test    # 真實 Git：裸遠端、兩個複本、選檔提交、鎖定拒絕、金鑰攔截、推送、自動快轉拉取、本機 HTTP 遠端的 401 → 登入、提交身分、自動接續排程與執行
node tests\git_browser.cjs   # 模擬主機：登入頁、提交身分、三種顏色、確認流程、金鑰提示、規則頁、自動接續設定、窄視窗
python tests\cli_smoke.py    # 真實倉庫的 /git、/git commit、/git never、/resume-auto
```

測試只使用暫存資料夾與 `CCA_DATA_DIR`，不碰使用者的專案或遠端，也不使用模型額度。`git-test` 另把 `GIT_CONFIG_GLOBAL` 指到暫存檔並設 `GIT_CONFIG_NOSYSTEM=1`，用一個回傳固定測試帳號的認證程式代替 Git 認證管理員；真正的 Git 認證管理員視窗與瀏覽器登入需要人操作，沒有自動化驗證。
