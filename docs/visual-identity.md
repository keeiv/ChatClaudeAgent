# 視覺識別（1.0.2-luna 起）

這份文件寫給之後改介面的人和 AI。CCA 是一個要盯著好幾個小時的工作區：主機在背後跑 Claude、GPT、Gemini 與本地模型，介面要讓人一眼看出誰在做什麼、哪些結果已經被主機確認過，其餘的東西都退到後面。

1.0.2-luna 以前的介面沿用 Discord 的版面（伺服器列、頻道欄、成員欄）、石墨色切角板與十六款選用主題。那套版面把工具藏在三層導覽後面，切角與點陣又讓每個表面都在爭取注意。這一版全部重做，舊的規則不再適用。

## 版面

- **左欄：對話列表。** 上方是搜尋（`Ctrl` + `K`），接著收件匣、訂閱與用量、插件商店；下面是「協作群組」與「私人訊息」兩組列。開啟中的群組在自己那一列下方展開工具（審查變更、版本控制、任務控制、交付驗證、群組設定），不再有另一層專屬側欄。最下方是帳號列與設定。
- **中間：對話。** 標題列只放名稱、一行設定摘要與少數動作；流程條在標題下方；訊息往下排；輸入框固定在底部。
- **右欄：檢視面板。** 一次只看一件事，用分頁切換：群組是「進度」（互審時間軸、任務紀錄、多代理狀態）、「成員」（目前誰負責什麼、額度）、「驗收與任務」；私訊是「狀態」、「權限」、「驗收與任務」。審查窗格與版本控制窗格開啟時，檢視面板讓出空間。視窗窄於 1200 px 時，檢視面板改成抽屜。

## 顏色

色票以 token 定義在 `ui/app.css` 的 `:root`，亮色與 Fable 的配色由 `config/themes.json` 產生（見 [介面外觀](themes.md)）。原生程式（CLI 與更新視窗）讀同一組十六進位 token，所以 token 名稱與 `#rrggbb` 格式不能改。

- **底色**是偏冷的鋼藍黑：標題列最深，側欄與檢視面板其次，對話區最亮，卡片再亮一階。深色模式靠明度分層，不用陰影。
- **天藍（`--signal`、`--brand`）只標三件事**：主要動作、目前選取、鍵盤焦點。不拿來當標題色或大面積底色；測試通過、驗收成立用狀態綠。1.0.2-luna 開發途中試過螢光萊姆綠，太刺眼，改成這個柔和的天藍。
- **成員識別色**：Claude 陶土、GPT 綠、Gemini 紫、本地審查員粉與琥珀。用在成員標記、作者名稱、流程節點與時間軸，不拿來當按鈕色。
- 狀態色：綠（通過）、黃（等你決定）、紅（失敗或危險）。需要你決定的卡片用黃色左邊線，不用斜紋或閃爍。

## 形狀與字

- 圓角分兩級：控制項 6 px、卡片與面板 10 px，對話框 14 px，標籤與徽記用膠囊。邊框是一像素的細線，不用外陰影區分層級（浮動層例外）。
- 字型只用 Windows 內建：介面 Segoe UI Variable／Segoe UI，中文落回微軟正黑體 UI；程式碼、路徑與數字欄用 Cascadia Mono。介面 14 px、對話 15 px（可在版面設定調整）。
- 成員頭像是畫出來的，不是上傳的：Claude、GPT、Gemini 與兩位本地審查員各是一滴成員色的水滴，尖端圓圓地朝左上方傾斜，右上方有兩顆深色的豎膠囊眼睛；使用者是一顆同樣風格的圓胖星星。全部是扁平色塊，沒有光影、白眼球或高光（1.0.2-luna 開發途中試過立體版本，看起來太嚇人）。形狀在 `ui/app.js` 的 `avatarSvg`，顏色只讀 token（`--claude`…、`--star`、`--avatar-eye`），所以亮色、暗色與插件配色都能用。不再有上傳頭像、橫幅或個人資料卡。使用者送出的需求顯示成卡片；AI 的回覆是正文，工具呼叫與檔案變更收在下方的活動列。

## 動態

動態只表示狀態：流程節點的呼吸與轉圈、交接的圓點、輸入中的點點。全部遵守 `prefers-reduced-motion`，`/motion off` 與桌面的同一設定可關閉。

## 不要做的事

- 不要加回伺服器列、成員欄、個人資料卡或徽章。
- 不要在元件裡寫死顏色；新元件只讀 token。
- 不要加漸層、玻璃擬態、發光陰影、點陣或裝飾性斜紋；頭像也維持扁平。
- 群組設定（主刀、模型、權限、資料夾、本地審查員、來回上限、流程圖）放在頻道設定面板 `opsPanel`，不要再擠進標題列。

## 標誌

程式圖標、介面標誌、字標與 CLI 點陣由不公開的圖標產生器以同一組 32 單位幾何產生：兩道相向的弧，淺色是撰寫，天藍是交回來的審查。特殊版本把右弧換成各自的顏色並在環內放符號。規格見 [CCA 圖標](brand-1.0.md)。
