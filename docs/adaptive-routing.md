# 依需求選擇模型與思考程度（1.0.0-terra）

在「使用者設定 → 自動模型與思考程度」分別調整 Claude 與 GPT。模型與思考程度是兩個獨立開關，按對話保存。選擇發生在每輪啟動前；同一輪執行中不切換，也不改變主刀、審查者、權限或工具。

新的對話預設開啟兩項自動選擇。舊對話若已保存手動模型或思考程度，該項保持手動；缺少設定的項目才自動啟用。從模型選單指定模型只關閉自動模型；指定思考程度只關閉自動思考。重新開啟自動模式仍保留原手動值作為後備。

## 選擇規則

主機先建立任務輪廓，再分別選模型與思考程度。不額外呼叫模型，也不把內部規則附進提示詞。

| 因素 | 檢查的內容 |
| --- | --- |
| 工作內容 | 文字修訂、概念解釋、局部修改、功能實作、故障排查、架構設計 |
| 影響範圍 | 單行／單一函式、跨模組、整個專案、不同檔案目標與多項要求 |
| 風險 | 資料完整性、權限與安全、併發狀態、正式運行環境；重複同詞不累加風險 |
| 推理需求 | 方案取捨、演算法、效能瓶頸、正確性證明與不變量 |
| 驗證要求 | 測試、回歸、重現、邊界案例與覆蓋率 |
| 限制 | 保留資料、既有行為、相容性、跨平台、依賴與資源預算 |

這些因素有分開的權重與上限。模型維持輕量、一般、深入三種方向；思考目標則分 low、medium、high、xhigh，由另一組分數決定。多個風險與約束同時存在時才提高複合負擔，單純貼很長的內容不直接選最深入模型。分數是本專案的路由政策，不是模型品質、正確率或信心百分比。

處理文字前先略過程式碼區塊、引用區塊、成對引號內容與部分終端機堆疊行；英文詞有單字邊界，工作／範圍詞也檢查相鄰的否定語句。「修改文案裡的『資料遺失』」與「修復資料遺失」因此不同。短定義與純文字修訂可維持輕量；特徵不足時採一般設定，不預設它很簡單。

「繼續」「照這個做」「繼續被中斷的工作」等明確延續語句，可沿用同一對話前一項使用者需求。最多向前檢查 12 則使用者訊息，略過連續的延續語句，單項前文上限 12,000 UTF-8 位元組；普通新需求不沿用舊風險。日常模式、明確指定模型與其他既有例外仍保持原行為。

預覽會列出各項判斷依據；每輪回覆及上下文來源保留決策。這仍是文字規則分析，沒有模型語意判讀：隱喻、未明說的背景、複雜否定與未涵蓋用語可能判錯。可先預覽並手動固定，不能宣稱每種任務都會選到最佳模型。

候選來自 Claude Code initialize 或 Codex model/list 的實際回報，不自行建立模型 ID。已知輕量家族包括 Haiku、mini、nano、luna、spark；一般家族包括 Sonnet、sol、terra 及可辨識的 GPT／Codex；深入家族包括 Opus、astra、pro。同級選項優先選較新的數字代次。這是 CCA 的路由政策，不能據此推論不同產品的實際能力或價格。

找不到同級時選最接近的已知候選；家族無法識別或尚未取得目錄時，沿用保存值或後端預設並說明原因。第一次尚未取得後端目錄時可能使用預設模型。圖片、音訊、嵌入及已隱藏的目錄項目不參與選擇。

思考程度只使用該模型回報的 `supportedEffortLevels`，選最接近 low／medium／high／xhigh 的支援值；沒有回報時使用後端預設，不猜參數。自動模型加上固定思考程度時，先篩選支援該程度的候選；目錄已有內容但沒有相容候選時停止並提示調整。

## 界線與紀錄

- 日常模式沿用既有的固定省額度設定。
- 多代理流程中的原生 Claude／Codex 節點可使用自動模式；節點明確填入的模型或程度各自保持固定。
- API、本地模型與獨立意見模式保持明確指定的模型。自動選擇不跨供應商切換。
- 回覆下方的「依需求選擇」顯示送出時的模型、程度及原因。上下文來源紀錄也保留相同決策；它證明 CCA 的交付設定，不能證明供應商內部實際執行的權重或硬體。
- 切換設定需等目前任務停止；只有原子保存成功才確認，失敗會還原記憶體設定。

CLI 使用 `/auto on|off [claude|codex]`、`/auto model|effort on|off [claude|codex]`、`/auto preview 需求`。`/model` 與 `/effort` 的明確選擇同樣停用對應項目。

實作：`src/task_analysis.cpp` 建立任務輪廓，`src/routing.*` 選擇目錄內模型及程度，`src/adaptive.cpp` 負責交易保存，`App::startAgent` 與多代理啟動路徑套用結果，`ui/appearance.js` 提供設定與預覽。`build.bat appearance-test` 使用假的 Claude 子程序核對實際 `--model`、`--effort`，不使用訂閱額度。
