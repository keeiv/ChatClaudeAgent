# 審查者測試守門與 MCP 工具描述釘住（1.0.1-sol）

這一版有兩項防線，都是研究後挑出來的：群組裡審查者改檔案時，用測試擋下讓測試變紅的修改；API 代理使用 MCP 工具時，擋下核准後被改動的工具描述。兩者都只看主機實際量到的結果，不採信模型的說法。

## 審查者測試守門

### 為什麼做

arXiv 2607.21656（2026 年 7 月的預印本，第 1 版，尚未經同行審查）在 116 個任務上比較「一個模型寫、另一個模型審查並修改」。它的結果不對稱：Claude 審查 Codex 的修改，通過率從 71.6% 升到 89.7%；Codex 審查 Claude 的修改，從 91.4% 降到 82.8%；Claude 審查自己的修改沒有變化。論文的審查者不能執行測試。

CCA 的群組正是這個流程：審查者會直接改檔案。單一預印本不能當成定論，但「審查者的修改可能讓原本通過的測試變紅」是可以直接量的事，所以不必等結論，用專案自己的測試把它擋住。

### 行為

在頻道設定面板（桌面）或 `/test-guard`（CLI）設定一行測試指令並開啟守門。之後每當審查（`review`）或複審（`recheck`）回合改了檔案：

1. CCA 在專案資料夾執行指令。結束碼 0 才算通過；通過就照原本流程交給下一位。
2. 結束碼不是 0，CCA 先用影子檢查點保存審查者改完的狀態，再還原到這一回合開始前的檢查點，對那個狀態再跑一次指令。
3. 還原後是綠的：審查者的修改造成測試轉紅，維持還原。聊天室出現「已還原」訊息（含測試輸出結尾），任務紀錄的 `regression_guard` 多一筆，下一位成員收到的審查者說明裡附上被還原的檔案、修改內容與失敗輸出，並知道處理時不能讓測試變紅。審查者的修改算作未解決的疑慮，不會被當成同意。
4. 還原後也是紅的：不是審查者的錯，CCA 把審查者的修改放回去，訊息標示「基準也是紅」，流程照常。

無法判斷的情況（指令無法啟動、逾時 10 分鐘）一律不還原，訊息寫「沒有驗證」。自查（`selfcheck`）和寫入（`write`）回合不受守門管；管線模式有自己的測試閘門。

### 指令與安全

- 指令由使用者在設定裡輸入，單行、500 字以內，不含控制字元；模型不能改它，`conv.settings` 只接受來自介面的設定。
- 指令寫進 `%APPDATA%\CCA` 底下的暫存 `.cmd`，經 cmd.exe 在專案資料夾執行，環境中移除 `OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`CLAUDE_CODE_OAUTH_TOKEN`；執行完刪除。這是使用者自己的指令，在使用者的電腦上執行，不是沙箱。
- 還原使用回滾功能同一套影子檢查點，需要 git。審查者改完的版本另存為標籤 `regression guard: reviewer result` 的檢查點，編號前 8 碼寫在聊天室的訊息裡；目前沒有一鍵套用它的按鈕，要找回得從 `%LOCALAPPDATA%\CCA\snapshots` 的影子倉庫取。
- 守門只在 CCA 開著時執行。測試與還原進行到一半關閉 CCA，專案可能停在還原後的狀態，審查者的版本仍在上述檢查點。

### 限制

- 守門只擋「測試變紅」。測試覆蓋不到的壞修改不會被攔下，綠燈也不代表修改正確。
- 專案沒有可靠的測試指令時，開了也沒用；指令本身不穩定（偶發失敗）時會誤判，因此第二次測試是綠的才還原。
- 測試跑兩次加上還原，會讓有修改的審查回合變慢。
- 不是每次都有基準：審查者不改檔案的回合不跑測試。
- 審查者修改被還原後，累計修改檔案數仍包含被還原的檔案。

## MCP 工具描述釘住

### 為什麼做

MCP 工具的名稱、描述與參數格式直接進入模型的上下文。伺服器可以在使用者核准後改掉描述，在裡面放新的指示（「rug pull」）。核准時只看過工具名稱是不夠的。

### 行為

只涵蓋 API 代理的 MCP 管理（`toolserver.*`）；Claude Code 與 Codex 的 MCP 仍由各自的插件頁管理。

- 「連線與工具發現」列出伺服器現在提供的每個工具：描述、參數格式、SHA-256 前 16 碼與釘住狀態。核准清單內的工具預設不勾，要使用者看過後自己勾選，再按「釘住所選工具」。
- 雜湊涵蓋工具的 `name`、`description`、`inputSchema`、`annotations`，用排序鍵、無空白的 JSON 計算，與欄位順序無關；`title` 與圖示不計。
- 釘住時主機會對伺服器重新取得清單，使用者看到的雜湊和當下一致才保存；使用者檢視後描述又變了，該工具被拒絕釘住。
- 工作程序在每次 `mcp_discover` 與 `mcp_call` 前都重新取得工具清單（含分頁，最多 10 頁）。描述與釘住的不同，`mcp_discover` 把這個工具隱藏並列在 `blocked`，`mcp_call` 直接拒絕。沒釘住的工具同樣不能呼叫。
- 改了指令或參數的伺服器，所有釘住都作廢；只啟用／停用不影響釘住；從核准清單移除的工具，釘住也會被清掉。
- CLI：`/toolserver-test <id>` 列出工具與狀態，`/toolserver-pin <id> <工具名稱…>` 釘住剛檢視過的工具。

### 限制

釘住只能發現「描述變了」。描述沒變、行為卻變了的伺服器，它擋不住；工具本身是否可信仍要靠使用者核准時判斷。既有的 MCP 設定升級後沒有釘住，工具會被擋下，直到使用者重新檢視並釘住。
