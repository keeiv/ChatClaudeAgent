# 群組導覽

實作日期：2026-10-26。協作群組改以獨立圖標排列在最左側，私人訊息留在首頁，群組的訊息、任務與設定資料沿用既有格式。

## 位置與操作

- 最左側第一枚 CCA 圖標開啟私人訊息，恢復上次查看的 Claude／GPT 私訊。訂閱與用量、插件及收件匣放在首頁側欄。
- 分隔線下方是各協作群組，圖標使用群組自訂頭像，未設定時顯示名稱前兩個字元。選取後，旁邊顯示群組名稱、專案和「協作對話」。
- 工作區入口直接連到既有審查、任務控制、交付驗證與成員名單。群組名稱的下拉選單可編輯資料、開啟設定、排序或進入清除／刪除確認。
- 建立群組的加號位於群組圖標之後。新群組排在末端；訊息活動不改變位置。
- 拖曳圖標可排序。右鍵或 Shift + F10 可開啟選單；聚焦圖標時按 Alt + 上／下方向鍵可移動位置。一般方向鍵、Home、End 只移動焦點，Enter 開啟。
- 未讀指示與待核准／提問數量顯示在各自的群組圖標。首頁圖標只合計私訊，收件匣仍涵蓋所有對話。
- 刪除目前群組後回到私人訊息。刪除最後一個群組會保留空圖標列與建立入口；首次安裝仍建立一個起始群組。

目前每個群組只有一份實際對話。左欄工具是可用功能入口，沒有新增多頻道、伺服器資料夾、遠端成員或社群申請機制。

## CLI

`/chat` 先列私訊，再依相同的固定順序列群組。`/groups` 顯示群組清單；`/groups up` 和 `/groups down` 移動目前群組並保存。CLI 不建立圖形側欄，資料與桌面版一致。

## 保存與相容

`settings.json` 的 `groupOrder` 記錄群組 ID 順序。沒有此欄位的舊資料依原儲存順序顯示；已刪除／重複／私訊 ID 被略過，未記錄的既有群組補在末端。`lastDm` 記錄最近開啟的私訊，不會被群組切換取代。

介面送出 `groups.reorder` 和請求識別，核心驗證清單與當下群組完全相符後原子保存。失敗時復原設定並回報真實順序；新增／刪除導致過期的清單也拒絕。介面在主機確認前維持原順序，拖曳途中不替換正在拖曳的原生 DOM。

對話 ID、內容、專案資料夾、成員、任務與頭像參照保持原格式，無須搬移歷史。測試一律使用隔離 `CCA_DATA_DIR` 與模擬後端，不修改實際使用者資料。

## 設計依據

Discord 的[群組私訊說明](https://support.discord.com/hc/en-us/articles/223657667-Group-Chat-and-Calls)將群組私訊列在 DM 清單；[伺服器示意](https://support.discord.com/hc/en-us/articles/360045138571-Beginner-s-Guide-to-Discord)則以左側圖標切換伺服器、旁邊顯示頻道。CCA 協作群組具有專案與任務，因此借用後者的導覽分工，保留自己的切角、石墨底與冰藍訊號色。Discord 的[資料夾操作](https://support.discord.com/hc/en-us/articles/360030853132-Server-Folders-101)作為後續參考，本次沒有實作資料夾。

## 驗證方式

`tests/group_navigation_browser.cjs` 在真實 Edge 檢查導覽、實際拖曳、鍵盤、未讀標記、工具入口、窄視窗與保存失敗。`build.bat profile-test` 檢查完整 ID 驗證、原子寫入失敗、重新啟動、舊設定、最近私訊及最後群組刪除。`tests/cli_smoke.py` 的 navigation 情境在 ConPTY 內建立群組、移動上下位置並核對保存結果。畫面與紀錄位於本機 `build/group-navigation/`。

本次實際結果：共用核心 573 項、個人資料與導覽保存 164 項、群組導覽 Edge 35 項、ConPTY 10 組情境全部通過。既有桌面整合 18 項、工作流程 DOM 40 項、協作 Edge 19 項、徽章 Edge 30 項、活動與性格 Edge 21 項、頭像工具 16 項、代理模型 Edge 27 項及交付驗證介面 9 項也通過。

群組導覽檢查包括：審查窗格與成員名單互切、1000 × 720 側欄抽屜，以及 1000 × 600 視窗中的捲動位置保留。活動測試補上等待下一個繪製影格的條件，避免把上一份 365 格畫面誤認為新回應；測試驅動器的取消鍵使用已定義的 `esc`。沒有變更模型協定或使用真實訂閱額度。
