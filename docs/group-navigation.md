# 對話列表與群組順序（1.0.2-luna）

桌面版左欄是一個列表：上方是收件匣、訂閱與用量、插件商店，接著是「協作群組」與「私人訊息」兩組。1.0.2-luna 以前的伺服器列（最左側的群組圖標）與群組專屬側欄已經移除，群組和私訊一直都在同一個列表裡。

- 每個群組一列：群組名稱縮寫的標記、名稱，以及一行狀態（專案資料夾、第幾輪、誰在做什麼、或「等你決定下一步」）。有待處理的請求時顯示數字，有未讀訊息時名稱加粗。
- 開啟中的群組在下方展開工具：審查變更、版本控制、任務控制、交付驗證、群組設定。
- 「協作群組」標題旁的 `+` 建立新群組；沒有群組時，列表顯示一個建立第一個群組的入口。
- 群組列可以拖曳排序；鍵盤上 `Alt` + `↑`／`↓` 移動，`Shift` + `F10` 或右鍵開啟選單（開啟、重新命名、群組設定、上下移動、建立、清除或刪除）。方向鍵、Home、End 在列之間移動焦點，不會打開對話。
- CLI 用 `/groups` 查看與調整同一份順序。

## 順序的保存

順序由主機保存（`settings.json` 的 `groupOrder`，`App::groupOrder()` 正規化）。介面送出 `groups.reorder`，內容必須剛好是目前所有群組 ID；主機原子保存成功後才回覆並更新畫面，失敗時保留原順序並顯示「群組排序未能儲存，原順序已保留。」。新訊息與工作狀態不會改變順序。刪除最後一個群組不會自動建立新的群組，私訊照常可用。

## 測試

- `build.bat profile-test`：順序交易、無效 ID、保存失敗、重啟後保留，以及刪除最後一個群組。
- `node tests\group_navigation_browser.cjs`：在 Edge 裡驗證群組工具、真實拖曳、鍵盤排序、未讀與待處理標示、窄視窗抽屜與保存失敗。測試使用隔離資料與模擬主機。
