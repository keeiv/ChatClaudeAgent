# 交付驗證

0.9.0 的桌面版與 CLI 共用相同的原生核心。驗證證據由主機執行程序或瀏覽器後建立，模型回覆不能自行產生「測試通過」記錄。

## 需求與驗收證據

對話側欄「交付驗證 → 需求與驗收證據」可以選擇計畫步驟、對應檔案及測試命令。命令使用 JSON 參數陣列，例如：

```json
["python", "-m", "unittest", "discover", "-s", "tests"]
```

執行前會顯示命令及專案位置，必須明確確認。直接執行 Python、Node 或測試執行檔，不接受 shell、`.bat` 或 `.cmd`。一般測試在選定的專案內執行，並非作業系統沙箱；若測試改變來源，這次結果不能標為通過。

每筆證據保存實際結束碼、耗時、有限長度輸出、來源指紋、對應檔案雜湊、計畫版本與時間。來源指紋排除 Git 忽略的檔案、套件、建置產物、環境檔與連結。單檔上限 16 MB、整份來源 192 MB、20,000 檔案；每份對話最多 80 筆證據。

收到模型的檔案變更事件，或按「重新核對來源」發現內容改變時，舊證據標為過期，並取消依附它的步驟驗收。計畫改版也需要重新驗證。這不是持續監控所有外部檔案變更的檔案監視器。沒有附主機證據的人工驗收仍可使用，畫面會區分兩者。

## 重現審查疑慮

審查窗格的「重現這項疑慮」可填入修正前 Git 版本、相同測試檔案、命令及預期失敗訊息。也可以請 AI 先建立最小測試，核對後才執行。

工具匯出指定提交及目前來源到兩個暫存目錄，將相同的重現檔案放進兩份來源，執行相同命令。必須同時滿足：舊版非零結束、包含指定失敗訊息、新版零結束、兩者皆未逾時。原始專案不會被切換版本。暫存目錄不複製套件與機密設定；需要預先安裝的執行環境，不適合依賴未準備之外部服務的測試。

命令最長 180 秒；輸出截斷到約 24,000 字元，並遮蔽已知格式憑證。驗證結束會清理其子程序；這項清理不是權限隔離，也不能保證遮蔽任意格式的敏感輸出。

## 網站即時預覽

「網站即時預覽」使用獨立 Edge／Playwright 工作階段，傳回畫面、網址、視窗大小、元素與瀏覽器錯誤。可切換桌面與手機寬度、點選、輸入、捲動。點選元素後可將元素資訊及修改意見送入目前對話。

操作驗收使用 `click`、`fill`、`expectText`、`expectVisible`、`expectUrl`；至少需要一個斷言，例如：

```json
[
  {"action":"click", "selector":"#submit"},
  {"action":"expectText", "selector":"#result", "value":"完成"}
]
```

保存的證據包含操作結果與 PNG 畫面。只接受 HTTPS 與本機 HTTP 網址，不接受本機檔案、跨來源頂層跳轉、下載或彈出視窗。瀏覽器看到指定網址，不代表已證實遠端網站部署的程式與本機來源完全相同；畫面與記錄會保留這項限制。

需要 Node.js、Microsoft Edge 及可載入的 Playwright。可用 `NODE_PATH` 指向既有套件，或自行安裝到開發環境；核心沒有加入 npm 執行依賴。沒有工具時會顯示失敗，不產生模擬通過結果。

## CLI

| 指令 | 用途 |
| --- | --- |
| `/evidence` | 列出證據與過期狀態 |
| `/verify 設定.json` | 執行測試；設定包含 `command`、`paths`、`step`、`label` |
| `/reproduce 設定.json` | 增加 `base`、`cases`、`expectedFailure` 執行兩個版本 |
| `/quality-check` | 重新核對來源指紋 |
| `/browser https://...` | 開啟獨立瀏覽器並顯示文字資訊 |
| `/browser-run 設定.json` | 執行操作；設定包含 `operation`，驗收使用 `verify` 與 `actions` |

CLI 使用相同的主機驗證與證據保存流程；瀏覽器畫面另存 PNG，終端機不繪製圖片。
