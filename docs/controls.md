# 流程管控、Git 與介面輔助（1.0.2-sol）

這一版把幾件「寫完以後」的事接進 CCA：AI 不該改的檔案、任務的用量、你自己還沒提交的修改、任務分支與 PR、衝突、排隊合併與排程。原則和既有功能一樣：只採信主機量到的結果，不靠模型的說法；動到 GitHub 或合併回主線的動作都要你按下才發生。

## 受保護路徑

頻道設定 → 受保護路徑（CLI：`/protect`、`/protect add 規則`、`/protect remove 規則`、`/protect off`）。每行一條，相對於專案資料夾，規則和「永遠不提交」相同：`資料夾/` 保護底下全部，`*` 不跨資料夾，`**` 可以跨，沒有 `/` 的規則比對任何一層的名稱（例如 `*.lock`、`docs`）。絕對路徑、`..`、控制字元一律拒絕，最多 40 條。

- AI 每一輪結束時（私訊、群組、多代理流程都一樣），主機先拍一個檢查點，和這一輪開始前的檢查點比對**實際**改了哪些檔案；不看後端回報的 FileChange（Gemini、Cursor 沒有回報）。
- 符合規則的檔案還原成這一輪開始前的版本（原本不存在的就刪掉），其他修改保留。AI 的版本另存檢查點，聊天出現紅色「已還原」訊息，寫明檔案與檢查點編號；群組的任務紀錄多一筆 `protected_reverts`，下一位審查者看到的修改清單不含被還原的檔案。
- 檢查完成前，這一輪的後續動作（交接、規範審查、下一個檢查點）都等它，所以不會有下一位在還原前開工。
- 這是事後還原，不是唯讀權限：AI 在這一輪裡仍可能讀取、執行或暫時改動這些檔案。需要 git；沒有檢查點時不檢查。

## 任務上限

群組的頻道設定 → 任務上限（CLI：`/limit 50 30`、`/limit off`）：Token 上限（萬）與時間上限（分鐘），0 表示不限。

- 所有成員回報的輸入加輸出 token 都計入這個任務（訂閱或 API 都算）；沒有回報用量的後端不計入。時間從任務建立算起。
- 交給下一位之前檢查；超過就暫停並說明用了多少。按「繼續」會從現在起再給一份同樣大小的額度；也可以結束任務。

## 開工前檢查你未提交的修改

群組或多代理流程的新需求送出時，如果專案資料夾在 Git 倉庫裡、而且資料夾底下有未提交的修改（只看專案資料夾這一層以下，不看倉庫其他地方），需求先保留，聊天列出檔案，讓你選「照常開始」或「先到版本控制提交」（CLI：`/start`）。目的是不讓 AI 的修改和你的混在同一份 Git 差異裡。私訊不檢查。設定 → 版本控制可以關掉（CLI：`/dirty-check off`）。不是 Git 倉庫的資料夾直接開工，不會多等。

## 系統通知

CCA 不在前景時，下列情況發 Windows 通知，點了會帶 CCA 到前景並打開那個對話：需要你核准或回答、協作或多代理流程暫停、完成或因額度停止、私訊的回覆超過 20 秒才完成、排程開始、合併佇列的結果。CCA 在前景時不發。設定 → 通知可以關掉。CLI 在同樣的時機響一聲終端機提示音（`/notify on|off`）。

通知用系統匣圖示的氣球通知，只在通知顯示時出現圖示，結束或點擊後移除。

## 用 @ 指定檔案

在輸入框打 `@`，CCA 列出專案裡符合的檔案（跳過 `node_modules`、`build`、`.git` 等相依與輸出資料夾，最多掃 20,000 個檔案），方向鍵選擇、Enter 或 Tab 插入 `@路徑`。可以加行數，例如 `@src/cart.ts#L10-20`。

送出時訊息原樣保留，另外附上一段「使用者用 @ 指定了下列路徑，回答前先讀取它們」，只列出專案裡確實存在的路徑與行數（`..`、不存在的路徑、電子郵件都忽略）。CCA 不把檔案內容塞進提示詞，由 AI 用自己的工具讀取。CLI：直接在訊息裡寫 `@路徑`，`/find 文字` 列出符合的檔案。

## 指令面板（Ctrl+K）

Ctrl+K 原本只能切換對話，現在先列出目前對話能做的動作：停止 AI、切換權限、換模型（Cursor 的模型選單）、開啟審查窗格、版本控制、受保護路徑、專案規則、接續中斷的任務、照常開始等待中的任務，以及新增群組、訂閱與用量、設定、通知設定；輸入文字篩選，方向鍵移動，Enter 執行。CLI 的 `/` 指令選單本來就是同樣的用途。

## 專案規則

頻道設定 → 專案規則或 Ctrl+K「專案規則」：直接編輯專案資料夾的 `AGENTS.md` 與 `CLAUDE.md`（Claude Code 讀 CLAUDE.md，其他成員與本地審查員讀 AGENTS.md）。

- 下方列出這個專案裡規範審查最常退回的原因，換成一行規則，按「加入」附到檔案最後；已經寫在檔案裡的不再建議。
- 保存時主機比對磁碟上的內容是否仍是你打開時的版本，被別處改過就拒絕，不覆蓋。只能寫這兩個檔名，AI 工作時不能保存。CLI：`/rules` 列出兩個檔案的位置。

## 流程範本

多代理流程編輯器上方可以「載入專案範本」或「存成專案範本」。範本存在專案的 `.cca/pipelines/<名稱>.json`（`{name, description, pipeline}`），可以和程式碼一起提交、在團隊間共用。

- 存檔與列出時都經過和「儲存流程」相同的驗證；無效的範本會標示原因、不能選。
- 載入只填進編輯器，還要你按「儲存流程」才會套用。範本來自倉庫，內容可能被別人改過，套用前請看過節點與模型。
- CLI：`/pipeline` 不帶參數列出範本，`/pipeline 名稱` 套用（同樣經過驗證）。

## 任務分支、PR 與 CI

群組任務完成後，檢視面板的任務紀錄多一列：

1. **提交到任務分支**：建立並切換到 `cca/…` 分支（你未提交的修改會一起帶過去），接著打開版本控制，預先選好這個任務改的檔案、提交訊息填好需求第一行。提交、推送照版本控制原本的規則（永遠不提交規則、提交前金鑰掃描、只帶選取的檔案），由你按下才執行。CLI：`/task-branch [名稱]`，再用 `/git`。
2. **開 PR**：用 GitHub CLI（`gh`，需先 `gh auth login`）建立 PR；標題是需求第一行，說明取自任務紀錄（需求、每次交接、跑過的測試指令與結束碼）。按下前會先確認。CLI：`/pr`。
3. **檢查 CI**：用 `gh pr checks` 讀取結果，顯示通過、進行中或失敗的數量。CCA 不自動輪詢。CLI：`/ci`。
4. **交回群組修正**：有失敗的檢查時，把失敗的名稱與 PR 連結當成新需求交給群組，請成員用 `gh run view --log-failed` 看原因、修正、重跑測試並提交到同一個分支。CLI：`/ci fix`。

## 衝突協助

隔離工作區（worktree）的「檢查能否合併」發現衝突時，多一個「請 AI 在 worktree 解衝突」（CLI：`/resolve`）：

- CCA 在**隔離工作區**裡把合併目標分支合併進任務分支（不提交），把有衝突的檔案列給 AI：逐一解開衝突標記、保留雙方的意圖、跑相關測試、`git add` 後 `git commit` 完成這次合併，不推送。
- 你的專案資料夾完全不受影響；解完後照原本的流程「檢查能否合併」→「合併已提交變更」，仍然要比對預覽的兩個提交。
- 隔離工作區有未提交的變更或已有進行中的合併時不開始；沒有衝突時立即取消這次合併，分支保持原樣。
- 直接在專案資料夾 `git pull --ff-only` 失敗（分支分岔）的情況不在這個功能裡，仍需自行處理。

## 合併佇列

隔離工作區對話框的「加入合併佇列」（CLI：`/merge-queue on|off`）。CCA 開著時，每 5 秒看一次佇列，一次只處理一個（最早加入的、而且成員沒在工作的）：先預演合併，沒有衝突才合併已提交的內容，然後移出佇列；有衝突或其他原因不能合併就移出佇列並寫明原因（可以先請 AI 解衝突再重新排隊）。合併結果會發通知。不會自動暫存或提交任何檔案。

## 排程任務

設定 → 排程任務（CLI：`/schedule 02:00 1-5 需求`、`/schedule remove ID`）：在指定的時間與星期，把你的需求送進某個對話，最多 30 個。

- 只在 CCA 開著時執行，每天最多一次；超過預定時間一小時才輪到（例如 CCA 當時關著）就跳過當天。
- 對話正在工作時這次不送出，聊天留一則說明。
- 群組的任務上限、開工前檢查、權限與所有確認照常適用；CCA 不會自動推送、開 PR 或合併。

## 驗證

- `.\build.bat test`：受保護路徑的比對與清理、`@` 路徑的解析（行數範圍、句尾標點、電子郵件、`..`、不存在的檔案）與檔案搜尋。
- `.\build.bat cursor-test`：完整私訊一輪裡替身真的寫入受保護檔案與一般檔案，主機只還原受保護的那些，訊息寫明檢查點。
- `.\build.bat takeover-test`：群組完成時發通知、關閉通知時不發；真實 Git 倉庫的未提交修改讓需求先保留、「照常開始」後開工、關掉檢查直接開工；任務上限擋下下一輪、「繼續」重給額度、時間上限；專案規則的讀取、建議、只覆蓋打開時的版本、拒絕其他檔名；流程範本的保存、拒絕越界檔名與無效流程、列出並標示無效範本；任務分支建立與拒絕危險名稱、沒有 PR 不讀 CI、失敗的 CI 交回群組；排程在時間到時送出一次、可以刪除；合併佇列把乾淨的 worktree 任務合併回來並移出佇列。
- `.\build.bat collaboration-test`：真實 Git 衝突在隔離工作區解開（專案資料夾不變）、提交後重新檢查並合併、沒有衝突時不留下進行中的合併。
- `tests\controls_browser.cjs`：受保護路徑與任務上限的設定、保留中的群組需求、`@` 選檔、Ctrl+K 指令面板、專案規則的建議與保存、載入流程範本不會直接套用、通知開關與新增排程。
- 沒有驗證：Windows 通知實際顯示與點擊（測試中不能再開一個桌面版）、用 `gh` 建立真實 PR 與讀取 CI（需要真的 GitHub 遠端）。
